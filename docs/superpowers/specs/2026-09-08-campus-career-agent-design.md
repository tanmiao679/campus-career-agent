# Campus Career Agent 设计说明

## 目标

构建一个真实可运行、可演示、可解释的 Java Agent 项目，用于支撑 AI 应用开发实习及秋招求职。项目优先体现招聘岗位常见的 Spring Boot、Spring AI、Tool Calling、会话管理、可靠性处理和工程测试能力，不以功能数量为目标。

项目在完成并验证前不写入简历。简历只记录已经实现、能够现场演示和回答追问的功能。

## 项目定位

- 项目名称：Campus Career Agent（校园求职助手 Agent）
- 仓库名称：`campus-career-agent`
- 目标用户：准备实习或秋招的大学生
- 核心场景：用户提交岗位 JD 或求职需求，Agent 自动选择工具完成岗位分析、学习计划生成和面试题生成
- 运行框架：Spring Boot 4.0.7 + Spring AI 2.0.1，直接使用官方 DeepSeek Starter
- 参考来源：Spring AI 官方 Tool Calling 文档，以及 Spring AI Alibaba Tool Calling 示例的业务组织方式
- 二创原则：保留开源许可证和来源说明，重新设计业务工具、数据结构、错误处理、测试与文档，不通过改名冒充原创

## 第一版范围

### 保留功能

1. Spring Boot REST API
2. Spring AI 2.0.1 接入 DeepSeek
3. Tool Calling 与结构化工具参数
4. 三个求职工具：
   - `analyzeJobDescription`：提取 JD 技术栈、岗位职责、学历要求和关键词
   - `generateStudyPlan`：根据目标岗位和能力差距生成分阶段学习计划
   - `generateInterviewQuestions`：根据岗位要求生成针对性面试题
5. 多工具自动选择与组合调用
6. 简单会话记忆
7. 最大工具调用次数限制
8. 参数校验与可读错误响应
9. 工具执行异常捕获和降级提示
10. 工具调用轨迹记录
11. 核心单元测试和少量端到端测试
12. 中文 README、架构图、调用流程图、启动说明和演示截图

### 第一版舍弃功能

- RAG、Embedding、pgvector 和文档上传
- MCP Server/Client
- 多 Agent、A2A、并行 Agent 和子 Agent
- Human-in-the-loop 审批流
- Redis、MySQL 和用户系统
- React/Vue 等独立前端工程
- Docker 与复杂可观测平台
- 爬取招聘网站或对接真实招聘平台
- 批量 LLM 自动评测

这些能力只有在第一版稳定且能显著提高求职竞争力时，才作为后续增量加入。

## 核心流程

1. 用户通过 REST API 提交问题、岗位 JD 和可选会话标识。
2. 服务端完成长度、空值和必要字段校验。
3. ChatClient 将系统规则、用户请求、会话上下文和工具定义发送给 DeepSeek。
4. 模型选择零个、一个或多个求职工具，并生成结构化参数。
5. 工具层再次校验参数后执行确定性业务逻辑。
6. 工具结果返回模型，由模型组织最终回答。
7. 系统记录工具名称、参数摘要、执行状态、耗时和错误摘要。
8. 达到最大循环次数或工具失败时，系统停止继续调用并返回明确的降级结果。

## 模块边界

### API 层

负责接收请求、验证基础字段和返回统一响应，不包含 Prompt 与工具业务逻辑。

### Agent 编排层

负责构造 ChatClient 请求、挂载会话记忆与工具、控制调用次数，并组织最终响应。

### 工具层

三个工具分别处理岗位分析、学习计划和面试题生成。工具接口保持独立，输入输出使用明确的数据对象。

### 可靠性层

集中处理参数错误、模型调用失败、工具异常、超时和循环次数超限，避免异常堆栈直接暴露给用户。

### 轨迹层

记录每次工具调用的工具名、参数摘要、状态、耗时和错误摘要。第一版使用内存记录或结构化日志，不引入数据库。

## 安全与配置

- DeepSeek API Key 只通过环境变量读取。
- `.env`、密钥、IDE 私有配置和运行日志不得提交到 GitHub。
- 仓库提供不含真实密钥的 `.env.example` 或配置示例。
- 日志不记录完整简历、手机号、邮箱和 API Key。
- 工具调用参数设置合理长度限制，拒绝空值和超长输入。

## 测试策略

### 不调用真实模型的测试

- 三个工具的参数校验与返回结构
- 空 JD、超长 JD 和缺少目标岗位等边界情况
- 工具执行异常后的统一错误响应
- 最大循环次数限制
- 调用轨迹的成功与失败状态

### 少量真实模型验证

使用 DeepSeek 完成少量固定测试，验证：

1. 单工具调用：只分析 JD
2. 组合工具调用：分析 JD 后生成学习计划
3. 面试题生成：根据 JD 生成问题
4. 非求职请求：不错误调用业务工具
5. 工具异常：能够停止或降级，不无限循环

## Token 与工作量控制

- 代码编译、参数校验和大部分测试不调用真实模型。
- 真实模型调用只用于验证 Tool Calling 决策和最终回答。
- Prompt 只注入当前任务需要的信息。
- 会话历史采用固定窗口，不无限累计。
- 工具循环设置硬性上限。
- 不进行无目的批量评测。
- 简单文件检查和重复性任务采用轻量处理；架构、核心代码和故障定位投入更深推理。

## 完成标准

项目只有同时满足以下条件才视为完成：

1. 新环境按 README 可以启动
2. 至少三个业务工具可独立测试
3. 模型能完成至少一次单工具和一次组合工具调用
4. 无效参数和工具异常有明确响应
5. 工具循环不会无限执行
6. 日志或接口能够查看调用轨迹
7. 测试通过且仓库不包含密钥
8. README 明确标注参考来源与个人实现内容
9. 用户可以独立解释核心流程和至少一个技术取舍
